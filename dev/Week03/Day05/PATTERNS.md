# PATTERNS.md

| Pattern | Where it is used later |
|---------|-------------------------|
| Repository | Data layer for database operations (Week 7) |
| Unit of Work | Save multiple database changes together (Week 7) |
| Strategy | Runtime behavior selection like payment methods (Capstone) |
| Observer | Events and notifications (Week 4) |
| Factory | Creating services and objects (Later projects) |
| Adapter | Integrating third-party APIs (Week 7) |
| Facade | Simplifying multiple subsystem calls (Capstone) |
| Builder | Building complex objects (Later projects) |
| Prototype | Cloning existing objects (Later projects) |
| Decorator | Adding logging, caching, validation (Week 7) |
| Command | Undo/Redo and queued requests (Later projects) |
| Template Method | Common algorithm with customizable steps (Later projects) |
| Mediator | Communication between modules (Capstone) |
| Chain of Responsibility | Validation pipeline or middleware (Week 7) |
| State | Workflow or status management (Capstone) |
